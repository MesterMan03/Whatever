## Whatever v0.8.0 - Mods inside the engine

This is a pretty big change to how Whatever runs games. Mods now run directly inside the engine, in isolated QuickJS Wasm VMs hosted by Wasmtime. The external JavaScript runtime and process IPC are gone. Games still ship ordinary TypeScript, JavaScript and JSON sources; the engine discovers and compiles them on the player's machine without external tools.

Every game is still just a mod collection. That includes Coinwatch, the new first-person survival game built with the same components, prefabs and APIs available to every other game.

### Direct engine access

Scene queries and mutations now execute synchronously on the simulation worker. Change a component, then read it again, and the next command sees that change immediately. Later mods see earlier mods' writes in dependency order. Physics integration follows script execution.

Component reads return live checked handles, including nested fields and native helper methods. `Scene.snapshot()` remains available when you want an immutable retained copy. Existing `Pending.get()` and `editComponent` helpers remain supported, but ordinary reads and writes no longer need them.

Each mod has its own VM and heap. The engine exposes its supported capabilities explicitly, with execution and memory limits. Mods have no ambient OS, process, socket or filesystem access; file and network operations go through engine APIs.

### Component references

A component field can now point directly to another component. For example, `session: RunSession | null = null` gives a pickup the session component it actually needs, including its methods.

The Inspector filters compatible targets. Scene loading, prefab instantiation and cloning preserve and remap these references. Coinwatch uses them for session callbacks. References resolve to instances within the same mod; communication between isolated mods still uses messaging.

### Prefabs, asset libraries and Coinwatch

- Reusable `.wprefab` entity trees, independent instantiation, and a searchable prefab catalogue in the editor.
- Portable `.wasset` ZIP libraries with editable meshes, textures, audio, scripts and prefabs. Imports remap namespaces into the receiving mod and preserve attribution.
- An official starter library with 131 prefab templates. Game objects remain authored data; their definitions do not live in engine code.
- Coinwatch: collect coins, shoot pursuing sentinels, and survive an arena assembled from starter assets. Movement, navigation, projectiles, scoring and restart behavior all live in mod scripts.
- Typed physical keyboard codes, immutable input snapshots, and mouse-button state and press queries for scripting.
- Asset-browser workflow improvements and clearer component-inspection progress in the editor.

### Simulation and presentation

The tick scheduler now catches up after short overruns without inserting an extra idle interval, fixing simulation slowdown. F1 shows the measured current TPS alongside FPS.

VSync frame acquisition runs off the window thread, with a reduced frame queue and rendering based on the latest available simulation state. This addresses the input latency and stuttering that previously made uncapped rendering feel noticeably better.

### Shared libraries and installers

The player, editor and `wmod` now share native engine, scripting and graphics libraries. The embedded VM/compiler payload ships once per distribution, and native dependency collection removes duplicate DLLs.

Windows/Linux portable releases put the actual executables and private libraries together in `bin/`, with support data at the root. macOS uses `Whatever Editor.app/Contents/MacOS`. Exported games retain their branded root launcher and put the player and libraries in `bin/`. Windows game launchers also include a playable DOS Snake stub.

- **Windows:** a standard MSI installs the editor, creates a Start menu shortcut and adds `bin/` to system PATH. Uninstall removes that PATH entry.
- **Ubuntu/Debian:** a DEB installs under `/opt/whatever-editor` and registers `whatever-editor` and `wmod` through `/usr/bin` links.
- **macOS:** a PKG installs the app in `/Applications` and registers its terminal tools through `/etc/paths.d`.

Portable archives remain available. Release CI includes relocation tests and installer checks. Linux targets Ubuntu 24.04's glibc baseline and uses system graphics/display drivers. Windows installers are unsigned; the macOS app is ad hoc signed and is not notarized.

### Updating from 0.7.0

Use **0.8.0** for the engine, editor, launcher, CLI and `@whatever-engine/api`. Replace the complete distribution together: native libraries and executables must come from the same build.

Mods distribute JS/TS/JSON sources, never precompiled Wasm. Keep imports limited to `@whatever-engine/api` and contained local sources. Code relying on host-runtime globals or external packages must use supported engine APIs instead. Restart Play after changing script sources or component schemas.

Source development continues to use stock Bun for package installation, scripts, tests and documentation. Build the SDK and guest with `bun run build:runtime` and `bun run build:guest`, then use `bun run build:native` to build native applications and stage their shared libraries. Installed editors and games need no development toolchain.
